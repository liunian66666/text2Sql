# 实习作品集版本收口清单

## 项目定位

本项目应定位为：**基于 DeepEye-SQL 的 RAG 增强 Text-to-SQL 数据分析 Agent 应用化改造**。

面试重点不是宣称提出了新的 Text-to-SQL 算法，而是说明如何把研究代码改造成一个可运行的应用：接入 OpenAI 兼容模型服务和云向量服务，封装单问题 Skill，增加只读执行与资源上限，提供 Web 演示入口，并用固定样本记录准确率、耗时和 Token。

## 当前已经具备

- 六阶段 Text-to-SQL 流水线和只读 SQL 执行。
- OpenAI 兼容推理接入：DashScope `deepseek-v4-pro-0813`（原生 tool calling，可关思考）+ 云端 `qwen3.7-text-embedding-flash` 向量。
- 单问题 `SQLSkill`，每次请求有独立产物目录。
- FastAPI + 静态单页演示站，支持 SSE 阶段进度。
- LangGraph ReAct 主图：LLM Planner ↔ Tool Executor，模型自主选择业务口径、Schema、SQL Skill 和可视化工具。
- 会话 ID、上下文记忆、系统 Prompt、结构化工具描述、工具调用轨迹，以及原生/JSON 两种工具调用协议。
- MCP Server 暴露数据库发现、业务口径、Schema 和只读 Text-to-SQL 工具。
- 查数、排名、趋势、占比、闲聊五类场景，以及指标卡、柱状图、折线图、饼图和表格。
- 可复现企业电商演示库（7 张表）、业务指标知识库和 6 个企业常用问题。
- 数据库白名单按"值索引是否用当前向量模型建好"暴露：当前是企业电商库（7 张表、示例题单、结果表展示）；5 个 BIRD 演示库待重建索引后回到白名单。
- 10 题端到端结果：集合式 EX 10/10，严格多重集 EX 9/10，可执行 10/10。
- Token、耗时、阶段日志、失败阶段和中断恢复记录。
- 只读连接、SQLite authorizer、SQL 超时、返回行数上限、请求 Token/时间熔断。
- 失控请求收敛：全候选被 `max_tokens` 截断时由 15 × 5 = 75 次重试改为 1 次调用即熔断。
- 29 项核心自动化测试通过（离线，不触网，约 4 秒）。
- 50 题、5 数据库三组对照已完成：仅生成 72%、生成＋修订 72%、完整流程 76%，三组均 100% 可执行。
- 企业库三题端到端实测（2026-10-27，DashScope deepseek-v4-pro + qwen3.7 向量，已关思考）：3/3 成功，平均 60.0 秒 Agent 墙钟、48.5 秒 SQL Skill、36,010 token 每题，0 次失败调用；结果用两种 SQL 写法独立复算一致（企业库是合成数据、无金标 SQL，因此不声称 EX）。旧自建端点下的 BIRD 三题 41.62 秒记录保留在 `evals/demo-fast/`，仅作历史对照。
- 启动自检 `--check-only`、重启后遗留任务标记 `interrupted`、演示站默认配置已切到 `demo-fast` 档。

## 发布前必须完成（P0，已完成）

### 1. 完成 50 题三组对照

状态：**已完成**。报告位于 `evals/bird-dev-50/ablation/`，代表性失败分析位于 `docs/failure-analysis.md`。

固定 50 题、5 个数据库即可，不追求官方全量榜单。输出：

- 仅生成 / 生成＋修订 / 完整流程的集合式 EX、可执行率。
- 总耗时、单题平均耗时、P95 和 Token。
- 每个数据库结果，以及修订/选择修复和破坏的题号。
- 3 至 5 个失败案例的原因分类。

验收标准：报告、JSON、CSV 都能生成，演示页可以直接读取结果；明确注明这是固定分层样本，不是 BIRD 官方成绩。

### 2. 增加“快速演示配置”

状态：**已完成**。配置模板位于 `config/template/demo-fast/`。旧自建端点下三个预设问题实测 32.71 至 47.31 秒；切换到 DashScope 后由企业库三题取代，实测 44.9–49.9 秒（SQL Skill 口径）。

当前 10 题正式配置平均每题约 151 秒、在线约 12.9 万 Token，不适合把成功寄托在现场网络和模型负载上。演示配置通过减少采样预算（4→1）与 few-shot 条数（7→5）压延迟；正式评测配置继续保留。

> 修正记录（2026-10-26，自建端点）：当时"关闭不必要的思考输出"**不可行**——自建端点对 `enable_thinking`（顶层与 `chat_template_kwargs` 包装）、`thinking_budget`、`max_thinking_tokens` 一律返回 500，模型为强制思考，延迟只能靠减少采样次数和每请求熔断来控制。
>
> 再次修正（2026-10-27，DashScope 兼容端点）：上面那条结论是**端点特定**的，不是模型特定的。实测同一条抽关键词请求：baseline 8.6 秒 / 378 completion token → `extra_body={enable_thinking:false}` **1.2 秒 / 30 token**（且关键词从 4 个增至 8 个）；`reasoning_effort=low` 2.0–2.2 秒；`thinking_budget=128` 被忽略（21.0 秒 / 969 token，反而更慢）。企业库单题因此从 250 秒失败变为 60 秒成功。

验收标准：三个预置问题连续运行成功；单题目标 30 至 90 秒；页面出现超时或预算熔断时给出可理解的提示。

## 建议加分项（P1）

- 一页中文架构与数据流说明。
- 失败案例页，展示错误分类与下一步改进，而不是只展示准确率。
- 一条 GitHub Actions：运行无网络单元测试。
- 录制 60 至 90 秒 GIF 或视频，避免简历查看者必须本地安装。
- 简历中的三条 STAR 描述与常见面试问题答案。

## 可以不做

- 不需要复现或刷新论文 SOTA。
- 不需要跑完整 BIRD-dev/test。
- 不需要训练或微调模型。
- 不需要多租户、登录、权限系统、分布式队列或 Kubernetes。
- 不需要支持任意数据库上传。
- 不需要为小幅准确率差异做显著性检验。
- 不需要复杂 React 重写；当前单页前端足够展示。

## 完成定义

当以下内容都可直接展示时，项目已达到实习作品集标准：

1. 一条命令启动页面。
2. 至少一个真实问题端到端成功并展示阶段、SQL、结果、耗时和 Token。
3. 页面能查看 50 题三组对照报告。
4. README 能在两分钟内解释个人贡献、工程难点和限制。
5. 无模型服务时仍能用离线结果完成讲解。
6. 核心无网络测试通过，配置模板不含密钥。
