# 企业数据分析 Agent 专项评测

## 评测范围

14 个案例覆盖能力问答、闲聊、查数、排名、趋势、占比、多轮改图、业务口径、用户提示、只读安全和空时间范围。检查项包括必需/禁止工具、意图、图表、SQL 状态，以及关键 SQL 语义。

## 结果

| 阶段 | 结果 | 说明 |
|---|---:|---|
| 首轮完整在线评测 | 11/14（78.6%） | 平均 49.2 秒，总计 390,194 token |
| 失败题修复后复测 | 13/14（92.9%） | 两项实质失败均修复；一项歧义题明确化后等待最终复测 |
| 最终增量回归 | 14/14（100%） | 切换 `deepseek-v4.1-flash-1017` 后最后一题完整通过，生成 SQL 正确使用用户提示 |

## 修复内容

1. 明确意图边界：只有总体构成才属于 `proportion`；退款率等业务比率属于普通查询；没有“排名/最高/Top N”的分类统计不自动视为排名。
2. 强制每个新数据问题先检索业务口径，再检查 Schema。修复“新客户”错误使用 `customers.register_date` 的问题；复测 SQL 已改为按客户计算首次有效订单日期 `MIN(order_date)`。
3. 用户提示案例改用数据库真实存在的渠道值，并新增 SQL 关键语义断言，避免“能执行但没使用提示”被误判为通过。
4. 评测脚本支持只重跑失败题，同时保留已通过结果，避免重复消耗模型额度。

## 解释边界

该报告衡量 Agent 工具策略和端到端行为，不是带金标 SQL/结果的 Execution Accuracy。`latest/summary.json` 是失败题增量回归报告：复用首轮已经通过的案例，只重跑失败案例，因此 14/14 不能表述为 `deepseek-v4.1-flash-1017` 的整批独立成绩。新模型另完成能力工具冒烟：2 次模型调用、1.834 秒、2,400 token。

原始首轮报告位于 `baseline-20261028/summary.json`，当前合并报告位于 `latest/summary.json`。
